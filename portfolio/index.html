The project

A complete movie shopping experience.

GT Movies Store is a full-stack Django web application that lets customers discover movies, learn more about each title, share reviews, and complete a purchase through a persistent shopping cart.

The process

From user stories to a working full-stack system.

I developed the project incrementally, but each feature was part of a larger architecture. I separated the application into focused Django apps, designed the database relationships, connected requests to server-side logic, and tested complete user journeys before deploying them.

A request first reaches Django’s URL configuration and is routed to the correct view. The view reads or updates data through Django models, prepares a template-data dictionary, and renders the appropriate reusable HTML template back to the user.

Application design

Four apps with clear responsibilities

Home handles the landing and about pages. Movies owns catalog search, detail pages, and reviews. Cart manages cart state, totals, checkout, orders, and line items. Accounts handles registration, login, logout, and order history. A shared base template keeps navigation and styling consistent across every screen.

Data design

Related models instead of duplicated data

The Movie model stores each title’s name, price, description, and image. Every Review connects a movie to its author through foreign keys. At checkout, an Order belongs to the logged-in user and contains Item records that preserve the purchased movie, quantity, and price.

State and security

A lightweight cart with protected actions

I kept the in-progress cart in the Django session as a movie-ID-to-quantity dictionary, so visitors can shop without creating database records prematurely. Checkout, order history, and review mutations use authenticated routes. Review ownership checks prevent one user from editing or deleting another user’s review.

End-to-end flow

Turning temporary selections into an order

When checkout begins, the server loads the selected movies, calculates the total from current prices and quantities, creates one Order, and creates an Item for each movie. It then clears the session cart and returns a confirmation containing the new order ID. The saved relationship lets the account page reconstruct past purchases.

  1. 01

    Translate user stories into routes

    I began by mapping each required action to a screen and URL: catalog browsing and search, movie details, cart review, account access, checkout, order history, and review management. This gave me a route-level plan before I wrote the implementation.

  2. 02

    Design the models and app boundaries

    I defined Movie, Review, Order, and Item models and connected them with foreign keys. I divided the code into independent Django apps so that catalog logic, account logic, and purchasing logic would not become mixed together as the project grew.

  3. 03

    Implement one complete flow at a time

    For each feature, I connected its URL, view, model query, and template before moving on. For example, search reads a query-string value, filters movie names case-insensitively through the ORM, passes the results into template data, and renders the updated catalog.

  4. 04

    Add authentication and ownership rules

    I used Django’s built-in authentication system and custom signup form handling rather than storing passwords myself. Login-required decorators protect private actions, while server-side ownership checks control which review-editing options each user can access.

  5. 05

    Debug through the entire request cycle

    When something failed, I traced it in order: confirm the URL matched, inspect the request method and submitted values, check the view’s branching logic, verify the database query, and finally inspect the template context. I used Django documentation and course examples to resolve framework-specific questions.

  6. 06

    Validate and deploy the production build

    I manually exercised both normal and edge cases, including empty searches, incorrect login credentials, an empty cart, unauthorized review edits, checkout, and persistent order history. I then configured the Django project for PythonAnywhere, migrated the database, served static and uploaded media files, and retested the live routes.
